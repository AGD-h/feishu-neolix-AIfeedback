# 2. 命题理解 & 落地思路

## 🔴 行业三大痛点

| 数字 | 痛点 | 具体表现 |
|------|------|---------|
| **7个** | 反馈渠道分散 | 运营需要在微信群、客服电话、抖音/微博、滴滴评价、车身扫码、车端告警等7个平台来回切换，响应慢、遗漏多 |
| **70%** | 人工分拣效率低 | 客服70%的时间花在读反馈、人工分类分级上，主观性强，P0安全事故易遗漏、P3咨询被过度响应 |
| **0条** | 反馈无法回流产品 | 大量有价值的用户声音淹没在工单系统中，产品团队凭"感觉"决策，缺乏数据驱动依据 |

---

## 💡 核心解决方案：零代码为主，轻代码为辅

以**飞书多维表格**为核心载体，零代码搭建工单池、AI字段、自动化流程和仪表盘；仅在三个环节用轻量Python脚本做补充：仿真数据生成、社媒舆情清洗、聚类周报自动化。

**为什么选择飞书？**

| 飞书能力 | 我们的用法 |
|---------|-----------|
| 多维表格 | 统一工单池，替代传统工单系统 |
| AI字段（分类/分级/摘要） | 替代人工客服分拣 |
| 自动化流程 | 自动分派、超时升级、满意度回访 |
| 仪表盘 | 运营看板，实时看数据 |
| AI问数 | 产品团队自由深挖数据 |
| 飞书群+消息推送 | 预警通知、周报推送 |

---

## 🏗️ 五层技术架构

**数据采集层** → **数据汇聚层** → **AI分析层** → **输出推送层**

| 层级 | 说明 |
|------|------|
| 📥 数据采集层 | 7种渠道统一接入：车身扫码、客服电话、微信群、社媒舆情、滴滴评价、车端告警、人工录入 |
| 🗄️ 数据汇聚层 | 飞书多维表格统一工单池，18字段标准Schema，全团队共用一套数据契约 |
| 🧠 AI分析层 | **交叉聚合双引擎**：DeepSeek做跨记录自动聚类，飞书AI问数做交互式深挖 |
| 📤 输出推送层 | 聚类周报自动生成、飞书文档输出、飞书群推送、P0异常实时告警 |
| 🔄 运营闭环层 | P0加急推送、SLA超时升级、满意度回访、状态流转跟踪 |
