# 飞书多维表格「AI 字段」System Prompt 优化模板
> 针对：**新石器无人配送车反馈工单池**（2026飞书AI先锋大赛命题）
> 使用方法：复制下方「提示词」部分，粘贴到飞书多维表格对应 AI 字段的「Prompt 规则」文本框，保存即可生效。
> 设计原则：Few-Shot 样例 + 场景关键词强规则 + 输出前自检，与 data/search_public_opinion.py 中 CLEAN_PROMPT 规则 100% 对齐，保证代码侧与 AI 字段侧分类标准一致。

## 📌 前置操作（先做这个！根治「无匹配类别」90%问题）

### 操作 1：单选字段选项文本 —— 统一使用中文（写入值 ≡ options 文本，100%匹配）

在飞书多维表格UI，打开「字段设置」，按下面配置**选项文本**（直接复制）：

| 字段 | 选项文本（按此顺序逐个添加） | Schema 对照 |
|---|---|---|
| **channel（渠道）** | 车身扫码、客服电话、微信群、滴滴评价、社媒舆情、车端告警、人工录入 | 对应 7 英文：scan_qr / hotline / wechat_group / didi_review / social_media / telemetry / manual |
| **category（类别）** | 安全、故障、体验、投诉、建议、**无匹配类别** | 对应 Schema 5 中文（最后一个是兜底，AI识别失败时用） |
| **priority（优先级）** | P0、P1、P2、P3、**无匹配类别** | 对应 Schema 4 英文（同上兜底） |
| **user_tier（用户层级）** | 网点经理、快递员、RaaS商户、收件人、路人社区、监管方、校园用户、商户、运维人员、普通用户 | Schema只用前6个；后4个是飞书端扩展人工补录可选 |
| **status（状态）** | 待处理、处理中、待回访、已闭环 | Schema 4 中文完全一致 |
| **contact_allowed（是否允许联系）** | 是、否 | （仅2项，不要加「未表态」） |

> 做完这一步后，我们的 Python import 脚本会自动把 CSV 里的英文枚举（如 social_media）转成对应中文（「社媒舆情」）写入，直接命中中文选项，**不会再落到「无匹配类别」兜底**。

### 操作 2：建议保留 feedback_id 为「自动编号」（如希望 S/H/M 前缀生效再改文本类型）

## 一、AI 字段：【category 工单类别】5 选 1

### 🎯 输出规则
只输出**一个中文词**，从：`安全 / 故障 / 体验 / 投诉 / 建议` 中选，**绝对不能输出其他词**。实在无法判断就输出你最有把握的那个，不要加标点、不解释。

### 🧠 分类定义 + 关键词强规则（命中就按下面分，置信度拉满）

| 输出值 | 含义 | 必中关键词（新石器无人车真实痛点） |
|---|---|---|
| **安全** | 人身/车辆/消防/监管类安全风险事件 | 撞、剐、刮、事故、摔倒、砸、压、受伤、流血、120、报警、110、监管、报备、整改、消防通道、违规、安全隐患、火灾、漏电、危险 |
| **故障** | 车辆/软件/充电/续航/网络故障导致运营中断 | 坏、坏了、故障、趴窝、停住不动、没电、卡住、卡顿、急刹、骤停、失灵、充不了、充电、续航、断网、无信号、死机、黑屏、跑偏、取件口打不开 |
| **体验** | 使用体验问题（无明显过激情绪） | 取件失败、找不到车、找车难、扫不开、扫码失败、太慢、速度慢、挡路、占道、挡着、绕路、位置偏、不认识、路线绕、等太久、电话打不通 |
| **投诉** | 明确表达不满/赔偿/举报等诉求 | 投诉、不满、差评、垃圾、赔偿、赔、退钱、退款、说法、举报、客服态度差、投诉到12315 |
| **建议** | 功能/路线/模式/改进提议或行业咨询讨论 | 建议、希望、能不能、优化、改进、应该、觉得可以、建议增加、路线规划、推广、扩张、政策、行业动态、展会、合作 |

### 💡 Few-Shot 示例（AI直接照此逻辑类推）
```
输入：沈阳无人车把大爷刮倒后留纸条，小亮送件途中剐蹭电动车致大爷擦伤，留下致歉纸条未获车主联系
输出：安全

输入：深圳暴雨后12台新石器无人车趴窝停运，多个小区全天无车可用，影响快递配送
输出：故障

输入：家楼下新石器车扫码3次都没打开，取件码发过来但车身屏幕一直转圈，急死了
输出：体验

输入：黑猫投诉：新石器无人车把我的快递弄丢了，打客服三天没人理，要求赔偿500元
输出：投诉

输入：中汽无人车智能科技杭州公司重组打造L4级，搭载激光雷达适配城市复杂路况
输出：建议
```

### ✅ 输出前自检（在心里默念 3 秒）
我输出的是不是正好是 5 个词中的一个？→ 是就输出，不是就重新根据关键词选一遍。

## 二、AI 字段：【priority 工单优先级】4 选 1

### 🎯 输出规则
只输出**一个英文代号**，从：`P0 / P1 / P2 / P3` 中选，不能输出其他值。

### 🧠 分级定义 + SLA 规则（与 category 联动）
| 输出值 | 含义 | SLA 响应 | 触发规则（★命中即强制，优先级最高） |
|---|---|---|---|
| **P0** | 安全事故/监管介入/人员受伤/交通事故 | **5 分钟内**响应 | category=安全 且 内容含：撞 / 事故 / 摔倒 / 受伤 / 120 / 监管 / 消防 / 交警 / 110 / 人员伤亡 / 财产损失严重 |
| **P1** | 运营中断（车辆趴窝/大面积故障/充电失败） | **30 分钟内**响应 | category=故障 且 内容含：趴窝 / 全断 / 大面积 / 充电失败 / 无法使用 / 停运 / 全天没车；或 category=安全但不够P0严重 |
| **P2** | 体验问题/投诉/一般安全隐患 | **1 小时内**响应 | category=投诉（默认 P2）；category=体验（默认 P2）；category=故障但局部问题（仅屏幕转圈不影响其他车） |
| **P3** | 建议/咨询/行业动态讨论 | **24 小时内**响应 | category=建议（默认 P3） |

### 💡 Few-Shot 示例（AI直接照此逻辑类推）
```
输入（category=安全）：沈阳无人车剐蹭大爷擦伤留纸条
输出：P0

输入（category=故障）：深圳暴雨后12台车趴窝停运
输出：P1

输入（category=体验）：扫码三次失败车身屏幕转圈
输出：P2

输入（category=投诉）：黑猫投诉丢快递要求赔偿
输出：P2

输入（category=建议）：讨论L4级无人车配置官宣
输出：P3

输入（category=安全）：车身贴了违规贴纸影响市容但没人受伤
输出：P1   ←（安全但不够P0级别，降一档）
```

### ✅ 输出前自检（3 秒）
1. 有没有先判断 category？→ P0/P1 必须基于 category=安全/故障才成立
2. 输出的是不是正好 P0 / P1 / P2 / P3 之一？→ 是就输出，否则重判
3. 有没有把「建议」分到 P2/P1/P0？→ 建议永远是 P3，除非内容里同时有严重投诉内容

## 三、AI 字段：【content_summary AI 摘要】优化

### 🎯 输出规则
35字以内精炼摘要，**必须包含三要素**：【来源平台/场景】+【核心问题点】+【关键影响对象】。不要废话、不要修饰词。

### 优秀案例参考（直接照着结构写）
- 微博舆情：无人车剐蹭老人留致歉条未联系车主
- 知乎舆情：暴雨后12台无人车趴窝运营中断
- 黑猫投诉：扫码三次失败车身屏幕转圈联系不上
- 微信群反馈：快递员反映车辆没电无法派件
- 社媒行业新闻：L4级无人车公司重组配置官宣待发

### 反例（不要写）
- ❌「车辆问题」→ 太笼统
- ❌「用户反馈说他今天遇到了一件关于无人车的很不愉快的事情」→ 废话太多
- ❌「新石器无人车差评」→ 没说清原因

## 五、【答辩加分展示】飞书 AI 字段 → Python 脚本「AI 分类链路闭环」

**演讲话术**：
> 我们整个分类分级体系采用了**代码规则 + 飞书 AI 字段**的双层架构：
> 1. 舆情采集进 CSV 时，Python 脚本的 DeepSeek prompt 已经根据新石器无人车真实痛点场景，用 Few-Shot + 专家关键词规则输出了第一轮分类分级（代码可控、可复现）；
> 2. 写入飞书多维表格后，飞书 AI 字段会再跑一遍同样逻辑的 prompt，结果如果和第一轮一致则直接采纳，如果不一致（比如剐蹭案例第一轮写成了体验 P2，飞书 AI 升级识别成安全 P0）→ 以飞书 AI 的实时判断为准，体现了「**规则兜底 + AI 动态升级**」的双层闭环能力。
> 3. 双语映射层（Schema 英文枚举 ↔ 飞书 UI 中文选项）保证了两边写入值 100% 命中飞书选项，不会出现「无匹配类别」的情况；之前 category 出现的「无匹配类别」绝大多数是因为我们之前写入了英文 social_media 但飞书 UI 只配置了中文选项，现在彻底修复了 — 剩下的「无匹配类别」才是真正的 AI 识别失败 case，是模型迭代的训练样本来源。
